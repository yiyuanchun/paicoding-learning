# 统一使用 paicoding-mysql 启动与验收

## 1. 当前部署目标

所有业务数据均使用现有容器 `paicoding-mysql` 中的 `pai_coding`。不迁移账号、文章，不创建独立测试数据库。

| 服务 | 容器 | 本机地址 | 持久化位置 |
|---|---|---|---|
| MySQL | paicoding-mysql | localhost:3307 | 原 paicoding-mysql-data 卷 |
| Redis | paicoding-redis | localhost:6379，DB 0 | 现有容器 |
| RabbitMQ | paicoding-local-rabbitmq-1 | localhost:5672；管理页 15672 | paicoding-local_rabbitmq-data |
| Elasticsearch | paicoding-local-elasticsearch-1 | localhost:9201 | paicoding-local_es-data |
| Canal | paicoding-local-canal-1 | localhost:11111 | paicoding-local_canal-data |

RabbitMQ 的 `mq_outbox`、`mq_inbox`、`mq_interaction_state`、`notify_msg` 与搜索的 `search_cdc_receipt`、`search_cdc_checkpoint`、`search_cdc_inbox`、`search_index_task`、`search_cdc_signal` 都在 `pai_coding` 中。搜索表在应用启动时由 Liquibase 创建。

通知链路：业务事务与 Outbox 一起提交 → RabbitMQ 持久化消息 → 消费幂等记录和站内通知一起提交 → ACK。

搜索链路：业务 MySQL 提交 → Binlog → Canal → 业务库持久化任务 → 查询文章最新完整数据 → Elasticsearch → 标记任务完成。

## 2. 首次准备

在项目根目录的 PowerShell 中运行：

```powershell
.\scripts\start-local.ps1 -InfrastructureOnly
```

脚本复用现有 MySQL、Redis，创建中间件专用网络 `paicoding-business`（172.30.91.0/24），把原 MySQL 接入该网络。它不会重建 MySQL 或修改其原来的 3307 端口和数据卷。

脚本把本机配置写入 Git 忽略的 `.env.local`，覆盖旧的 ES 地址和开关，生成并保存中间件随机密码。密码不会输出到终端；不要提交或分享 `.env.local`。

**Canal 专用账号是完整启动的前置条件。** 已在用户明确授权后创建 `paicoding_canal`，仅允许 `172.30.91.10`（固定 Canal 容器地址）连接。所需权限是 `pai_coding.*` 的 SELECT，以及 MySQL 协议要求的 REPLICATION SLAVE、REPLICATION CLIENT。后两项是实例级权限，可读取实例 Binlog，所以需要明确授权。账号没有业务数据写权限，不允许任意来源连接，不更改 root 权限。

启动脚本只检查该账号是否存在，**不会创建账号、修改权限或重置密码**。账号未准备好时，仅启动 RabbitMQ 和 ES 服务，保持 `PAICODING_ES_OPEN=false`、`PAICODING_CANAL_ENABLED=false`，并明确提示；完整启动会停止，避免误以为同步已成功。账号准备好后重新执行脚本才启用搜索链路。

当前 MySQL 已核验 `log_bin=ON`、`binlog_format=ROW`、`binlog_row_image=FULL`、`server_id=1`，无需重启或修改 Binlog 配置。

本机 Canal 关闭 TSDB 的全实例表结构快照，按订阅表读取元数据，避免为读取系统库扩大专用账号权限。该配置适用于当前 DML 增量同步；修改业务表结构时应暂停同步、升级查询及映射并重新补建，不支持跨历史 DDL 自动还原表结构。

## 3. 日常启动

首次授权和账号准备完成后：

```powershell
.\scripts\start-local.ps1
```

脚本启动三项中间件、使用 Java 8 构建，再启动 Spring Boot。页面地址以启动日志为准，一般为 `http://localhost:8080`。现有 `.dev-port` 可能选择已保存端口。

未修改 Java 代码时可跳过构建：

```powershell
.\scripts\start-local.ps1 -SkipBuild
```

使用 IDEA 时，先执行 `-InfrastructureOnly`，再用 JDK 8 启动 `QuickForumApplication`，工作目录设为项目根目录。项目会自动读取 `.env` 和 `.env.local`。确认 IDEA 没有覆盖指向 3308、3309、6380、5673 或 9202 的旧测试参数。

`scripts/start-search.ps1` 已兼容转发到统一入口，不再另外创建搜索服务。历史 `docker-compose.mq.yml`、`docker-compose.search.yml` 和带 `-test` 的文件仅保留历史开发用途；本机启动使用 `docker-compose.local.yml`，不要同时启动旧部署占用相同端口。

## 4. 在业务库验收 RabbitMQ

1. 打开 `http://localhost:15672`，使用 `.env.local` 的 `PAICODING_MQ_USERNAME`、`PAICODING_MQ_PASSWORD` 登录。
2. 查看 `paicoding.interaction.exchange` 和 `paicoding.notification.queue`、`paicoding.statistics.queue`、`paicoding.activity.queue`、`paicoding.interaction.dead.queue`。应为持久化队列。
3. 用账号 A 对账号 B 的文章评论、回复、点赞、收藏，再关注 B。查看 B 的通知页面；自己操作自己的内容可能按业务规则不产生通知。
4. 在 Navicat 连接 `localhost:3307/pai_coding`，执行以下只读查询。Outbox 最终为 SENT；Inbox 按消费者及 event_key 唯一。

```sql
SELECT id,event_key,status,retry_count,last_error FROM mq_outbox ORDER BY id DESC LIMIT 20;
SELECT consumer_name,event_key,processed_at FROM mq_inbox ORDER BY processed_at DESC LIMIT 30;
SELECT id,notification_key,last_event_key,last_event_version,visible FROM notify_msg ORDER BY id DESC LIMIT 20;
```

队列消息数为 0 不表示没有使用 RabbitMQ，正常消费者会迅速取走并确认；结合管理页消息速率、连接和 Inbox 记录判断。

## 5. 在业务库验收 Elasticsearch + Canal

1. 首次启动等待现有文章建立索引；查看 `http://localhost:9201/paicoding_article_v2/_count`。
2. 搜索文章标题中的词语，页面应显示高亮。英文拼写偏差可使用现有英文标题验证 AUTO 模糊匹配；中文使用内置 CJK 分词。
3. 修改一篇你自己创建的文章标题或正文，等待数秒后搜索新词。也可以在 Navicat 修改自己的测试文章后提交事务，以证明同步依赖 Binlog 而不是 Java 写入事件。验证后恢复该文章。
4. 查看任务表中的 `requested_version=completed_version`，以及 ES 中对应文章的最新内容。

```sql
SELECT index_name,initialized,last_position,updated_at FROM search_cdc_checkpoint;
SELECT article_id,requested_version,completed_version,retry_count,last_error
FROM search_index_task WHERE index_name='paicoding_article_v2' ORDER BY updated_at DESC;
SELECT task_type,subject_id,ready,done FROM search_cdc_inbox ORDER BY id DESC LIMIT 20;
```

管理员也可访问 `GET /api/admin/article/search/status` 查看同步状态，或调用 `POST /api/admin/article/search/rebuild` 补建现有文章。非公开、已删除文章不会出现在公开搜索，受限正文不进入公共索引。

业务库验收不要运行历史 `test-search.ps1`、`test-mq-persistence.ps1`：它们专为隔离环境设计，包含重启中间件等测试。不要直接将集成测试的数据清理语句指向业务库。

## 6. 停止与数据保留

在运行 Spring Boot 的终端按 Ctrl+C 停止应用。中间件可单独停止：

```powershell
docker compose -p paicoding-local -f docker-compose.local.yml --env-file .env.local stop
```

这不会停止原 MySQL，不删除数据卷。此前的六个 `paicoding-mq-it-*`、`paicoding-search-it-*` 测试容器已停止并保留数据；本方案不会启动它们。

接入前的业务库快照保存在 `logs/business-backups/`，该目录被 Git 忽略。实际验收结果见下节。
